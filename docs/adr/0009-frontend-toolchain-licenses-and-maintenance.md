## Context

PRD Q1 (2026-10-17) chose a Svelte 5 + Vite + TypeScript single-page application. Node.js is needed to build and develop the UI, not at runtime (F-WEB-3); the build output is embedded into the binary. ADR 0001 recorded that Vite, TypeScript and Node.js had not been checked with its method, and its decision Q10 postponed transitive dependencies until a real dependency graph exists. The spike `experiments/web/Ui` is that graph.

The license policy and criteria of ADR 0001 apply unchanged: GPL-3.0-or-later for shelf, GPL-3.0-compatible dependencies (judged against the FSF list, ADR 0001 S1), maintenance flag if there is no release in 12 months, no commit in 6 months, or a single maintainer without an organization. This ADR is an engineering assessment, not legal advice.

**What is and is not shipped.** None of the packages assessed here is part of the shipped binary. Only the build output of the UI (JavaScript, CSS and HTML generated by Vite and Svelte) is embedded; for that output the licenses of the build tools do not apply as such. Svelte's runtime code, which Svelte compiles into the bundle, is MIT (ADR 0001 row 22).

**Method.** npm registry metadata (`npm view`), the lock file and the installed `package.json` files of `experiments/web/Ui`, GitHub repository metadata (license, releases, commits, contributors), the Node.js release schedule (`nodejs/Release`, `schedule.json`) and the FSF license list. Everything was retrieved read-only on 2026-10-17. License values come from package metadata fields, not from license files, except for Node.js (LICENSE file read). Release counts are taken from the first 100 releases the GitHub API returns (newest first), so a number near 100 would be a lower bound; none is.

## Candidate notes

### T1. Node.js

- License: `LICENSE` starts with "Node.js is licensed for use as follows" and the MIT text (S1). GitHub reports NOASSERTION because the file also lists the licenses of bundled components; those were not individually assessed here. Compatible (Expat license, ADR 0001 S1).
- Release lines on 2026-10-17 (S2): v24 "Krypton" is LTS since 2025-10-28, moves to Maintenance on 2026-10-20 and ends 2028-04-30; v26 is Current, becomes LTS on 2026-10-28 and ends 2029-04-30; v22 ends 2027-04-30; v20 ended 2026-04-30; v25 ended 2026-06-01. Latest registry versions: 24.22.0 and 26.12.0 (S3).
- Compatibility with the toolchain: Vite 8.3.4 requires Node `^20.19.0 || >=22.12.0`, `@sveltejs/vite-plugin-svelte` 7.3.1 requires `^20.19 || ^22.12 || >=24` (S6, ADR 0007 R7). Both v24 and v26 satisfy them.
- **Measured:** `npm ci` and `vite build` of `experiments/web/Ui` with Node.js 24.22.0 and with Node.js 26.10.0 produce a byte-identical `assets/index-DlPIIf_m.js` (SHA-256 `44b4463e...5862`) and `index.html` (`ffc58a5c...ca8`). The CSS file was not compared. So the choice of the line does not change the JavaScript output in this setup.
- Verdict: **adopt**; the version policy is below.

### T2. npm CLI

- License Artistic-2.0 (registry metadata, S4). The FSF list says the Artistic License 2.0 is a free software license compatible with the GPL thanks to the relicensing option in section 4(c)(ii) (S5). npm is a build tool and is not shipped.
- The local npm is 11.19.1 (bundled with Node.js 26.10.0 and also used with the Node.js 24.22.0 test); the registry's latest is 12.2.0. Which npm version a given Node.js line bundles was not checked. Maintenance of `npm/cli` was not assessed in detail.
- Verdict: **adopt**, as part of Node.js.

### T3. Vite

- MIT (registry and repository, S6, S7). Organization `vitejs`; top contributors yyx990803 (1922), sapphi-red (1904), patak-cat (1010), bluwy (602). Last push 2026-10-16. Not flagged.
- Direct dependencies of 8.3.4: `lightningcss`, `picomatch`, `postcss`, `rolldown`, `tinyglobby`; optional `fsevents`; many optional peers (esbuild, sass, terser, ...) which are not installed in the spike. Verdict: **adopt**.

### T4. `@sveltejs/vite-plugin-svelte`

- MIT, organization `sveltejs` (S6, S8). Top contributor dominikg (500) and bots; bluwy (84). Not flagged. Verdict: **adopt**.

### T5. TypeScript 7

- Apache-2.0 on the registry and in the repository (S6, S9). Version 7 is the native port: the npm package pulls one optional platform package `@typescript/typescript-<os>-<arch>` (20 are listed in the lock, one is installed per machine), all Apache-2.0. The staging repository `microsoft/typescript-go` is **archived** (last push 2026-08-31); the registry and the releases point to `microsoft/TypeScript`, which is active (last push 2026-10-17, 100+ commits in six months, v7.0.2 released 2026-08-20). The details of the move were not looked up.
- `vite build` does not run the TypeScript compiler; the spike never ran `tsc` or `svelte-check`, so TypeScript 7 was **installed but not exercised**. Verdict: **adopt**; the type-check step is a task of the first web slice.

### T6. Rolldown

- MIT, organization `rolldown` (top contributors hyfdev 1720, IWANABETHATGUY 1414, shulaoda 1091). Native binary per platform as optional packages (15 in the lock, one installed). Version pinned by Vite as `~1.2.12`. Not flagged. Verdict: **adopt**.

### T7. lightningcss

- **MPL-2.0** (registry and repository; its 11 platform packages in the lock are MPL-2.0 as well, S6, S11). Per the FSF list MPL 2.0 is a free software license with indirect compatibility with the GNU GPL version 3 and later: section 3.3 allows combining MPL files with GPL-covered work and distributing the combination under the GPL, with the condition that the MPL-covered files remain available under the MPL (S5). It is a file-level (weak) copyleft; the tool is used only at build time and none of its code is shipped in shelf, so the condition does not arise.
- Maintenance: organization `parcel-bundler`; one contributor (devongovett) accounts for most commits; 3 stable releases in the last 12 months, the last on 2026-07-20; last push 2026-10-08. Not flagged by the rule (an organization exists), but the concentration is noted. Verdict: **adopt, with note**: it is a hard dependency of Vite 8, so replacing it is not an option of ours.

### T8. PostCSS

- MIT (S12). 24 stable releases in the last 12 months, last 2026-10-12. Verdict: **adopt**.

### T9. fsevents

- MIT (S13). Optional, macOS only, dependency of Vite (`npm ls fsevents`). **Flag:** latest release 2.3.3 from 2023-08-21, last push 2024-09-03. The package carries a prebuilt `fsevents.node`.
- npm 11.19.1 warns "1 package has install scripts not yet covered by allowScripts: fsevents@2.3.3 (install: (install scripts present))" and offers `npm install-scripts ls`, `approve` and `deny`. **Measured:** `npm ci --ignore-scripts` followed by `vite build` produces the identical output (same SHA-256 as above), so the build does not depend on the install script. What the script does was not examined.
- Verdict: **adopt, with note**: it is optional and not needed for the build; the flag does not reject it.

## Transitive tree of `experiments/web/Ui`

`package-lock.json` has 85 entries; 42 packages are installed on `osx-arm64` by `npm ci` (ADR 0007 R7 said 41, counted from the first `npm install`); the other 43 entries are optional platform packages (rolldown, lightningcss and TypeScript binaries for other platforms) that npm skips on this machine. License field of all 85 entries: MIT 47, Apache-2.0 24, MPL-2.0 12, ISC 1 (picocolors), BSD-3-Clause 1 (source-map-js). No entry lacks a license field. The licenses come from metadata, not from license files, and the entries were not assessed individually for maintenance. All of ISC, BSD-3-Clause (FSF "Modified BSD license") and Apache-2.0 are GPL-3.0-compatible (S5). The 12 MPL-2.0 entries are lightningcss and its 11 platform packages (T7).

## Decision

Toolchain verdicts: **adopt T1-T9**; no candidate is rejected and none violates the license policy. Notes: T7 (MPL-2.0, build time only) and T9 (maintenance flag, optional, not needed for the build).

**Node.js version policy: Node.js 26, decided by the project owner on 2026-10-17.** The major line is pinned as `26` in `.node-version` and in CI (`actions/setup-node`); the lock file (`npm ci`) pins the packages. Node.js 26 is "Current" until it becomes LTS on 2026-10-28 (end of support 2029-04-30). Facts behind the decision: the output of the UI build was identical under Node.js 24.22.0 and 26.10.0; v24 is the current LTS but enters Maintenance on 2026-10-20 (end 2028-04-30); v26 becomes LTS on 2026-10-28 (end 2029-04-30). Options that were considered: (a) pin the major line `24`; (b) pin the major line `26`; (c) allow `>=24` without a pin. (b) was chosen: it has the longest support window and Vite and the plugin support it. `experiments/web/.node-version` keeps the exact version used for the spike run (v26.10.0) as a record.

## Consequences

- **First web slice (M4):** put `package.json` and `package-lock.json` under version control (the repository root `.gitignore` ignores both; `experiments/web/.gitignore` has the negation), commit the exact-version `devDependencies`, use `npm ci` only, pin Node.js in CI with `actions/setup-node` and a `.node-version` file, add the type-check step (`tsc` or `svelte-check`) that this spike did not run, and decide the `allowScripts` entry for `fsevents` (`npm install-scripts deny fsevents` is the candidate; the build does not need it).
- **`THIRD-PARTY-NOTICES`:** nothing from this toolchain is shipped; the notices file needs the Svelte runtime notice (MIT) and the notices of any JavaScript that ends up in the bundle (the spike's bundle contains Svelte's runtime only).
- **Re-check triggers:** a Vite or Svelte major version, a new npm dependency in the UI, a license change in lightningcss or rolldown, Node.js leaving its support window, a TypeScript compiler requirement from Svelte tooling.
- **Not assessed:** the maintenance of each of the 85 transitive packages, the license files (only metadata), the bundled third-party licenses of Node.js, the content of the fsevents install script, how `microsoft/typescript-go` was merged into `microsoft/TypeScript`.

## Update from M4 slice `m4-ui-toolchain` (2026-10-18)

The first web slice put the toolchain into the repository (`src/Shelf.Web.Ui`) and settled the points that this ADR left open.

- **TypeScript 6.0.3 instead of 7.0.2 (T5).** The type check for `.svelte` files is `svelte-check` 4.7.7 (MIT, organization `sveltejs`), which declares `typescript` `^5.0.0 || ^6.0.0` as a peer. With TypeScript 7.0.2 `npm ci` stops with `ERESOLVE`; with 6.0.3 `svelte-check` reports 0 errors on the UI and `vite build` is unaffected (it does not run the compiler). This is the "TypeScript compiler requirement from Svelte tooling" that the re-check triggers named. TypeScript 6.0.3 is Apache-2.0 (the T5 verdict applies) and from the same organization. Moving to 7 is a re-check when `svelte-check` supports it.
- **`svelte-check` 4.7.7** is a new devDependency (MIT); the other versions are those of the spike: `svelte` 5.57.2, `vite` 8.3.4, `@sveltejs/vite-plugin-svelte` 7.3.1. The lock file is committed; the build uses `npm ci`. Not assessed: the maintenance of the packages that `svelte-check` adds (the total is 102 entries in `npm ls --all`, up from 85 in the spike).
- **fsevents (T9).** Decided: `.npmrc` sets `ignore-scripts=true`. The build is identical without the install script (measured above), and a build tool has no reason to run code at install time.
- **Node.js 26** is pinned in `.node-version` (`26`), used by `actions/setup-node` in CI; `package.json` says `engines.node >= 26`.
- **The `.gitignore` negation** is in `src/Shelf.Web.Ui/.gitignore` (a nested file overrides the root's `package.json` and `package-lock.json` patterns).
- **Still open:** `THIRD-PARTY-NOTICES` (M5): the Svelte runtime (MIT) is the only third-party code in the bundle so far.
